# Orka 1.3.2 — bounded long-running provider responses

Orka now separates provider response timeouts from local tool-command timeouts.
Direct API workers and the native Claude admission gateway both honor
`llm.budgets.provider_read_timeout_seconds`, which defaults to 900 seconds.

This prevents high-reasoning or large-output turns from failing at the former
hard-coded 120-second boundary. The timeout remains finite and the controller's
worker lifetime still provides an outer bound. A timed-out request is still
ambiguous: Orka retains its spend reservation and will not resubmit it blindly.

Provider health probes retain their intentionally short timeout and therefore
continue to detect unavailable routes quickly.
