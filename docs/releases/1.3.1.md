# Orka 1.3.1 — Anthropic context editing and accurate gateway failures

Claude ticket workers launched from either a Codex or Claude controller can use
bounded Anthropic context editing. Orka derives the required
`context-management-2025-06-27` beta header from validated context-editing payloads.
Tool-result clearing and thinking-block clearing are supported; unmetered
server-side compaction and unknown editing strategies remain rejected before
submission. Existing output caps, reservations, and usage settlement still apply.

A stopped native gateway now preserves its first failure and error type. An
upstream HTTP 400 remains HTTP 400 on retry instead of becoming a false HTTP 402
budget refusal. Actual budget refusals still return 402. Anthropic rejection of
`context_management` creates a shared compatibility hold so other tickets cannot
repeat the same failure.

Validation includes gateway regressions, a header/body transport test, rejection
of unmetered compaction, and an isolated live `claude-sonnet-5` context-editing
request with settled usage (12 input tokens, 4 output tokens). No sprint work was
started by that live check.
