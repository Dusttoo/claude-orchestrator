# Orka 1.1.0 release candidate

This release improves sprint completion and bounds spending while preserving
independent review and merge gates.

- Recover known terminal review failures without consuming a substantive round
  for rejected requests; account for design, code, and security separately.
- Keep independent tickets moving around isolated failures and temporary shared
  budget pressure. Preserve PR and branch identity through recovery.
- Complete decomposition dependencies and Jira readiness transitions. Generated
  children require migration ownership and explicit test plans.
- Enforce native API request reservations and worker watchdogs for supported
  direct Claude and Codex launches, including shared nested-worker allowances.
- Apply phase budgets and transfer unused, unreserved design allowance after
  verified approval. Total ticket and sprint ceilings still apply.
- Verify progress from Git trees, design receipts, independently closed findings,
  GitHub PR/CI observations, and controller-executed JUnit tests.
- Report completion, spend, recorded blocking, repeated findings, and optionally
  GitHub-confirmed merges.

## Adoption

Configure explicit pricing for every API model, including native auxiliary
models. Cooperative automatic recovery is an explicit opt-in and assumes workers
do not escape their process sessions. Existing unconfigured repositories retain
strict recovery requirements. Rescope old decomposition assessments that lack
`migration_owner` and `test_plan`. Configure `progress_tests` commands that emit
JUnit reports to `ORKA_TEST_REPORT` to enable test-progress receipts.

Native gateways support a documented subset of API execution. They do not meter
subscription sessions or arbitrary programs using other endpoints. Codex
compaction, hosted paid tools, background/stateful requests, and premium tiers
are rejected. These are cooperative spending controls, not an OS sandbox.

## Validation status

Offline coverage includes a continuous sprint scenario spanning design retries,
invalid review output, repair, both review gates, CI, mocked merge confirmation,
and dependent-ticket release while an over-budget ticket remains isolated.
Installed Claude Code 2.0.30 and Codex 0.147.0 complete mock-provider executions.
The optional Bedrock SDK suite was run with boto3 installed.

Live provider billing and sandbox Jira workflow checks require configured
credentials and a designated test project; they are not claimed by offline tests.
