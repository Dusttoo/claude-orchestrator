# Orka 1.3.0 — provider-aware sprint admission

Sprint admission now verifies resolved worker routes before reserving attempts.
Native launchers must match the configured provider, explicit model, and effort;
API batch preparation and submission must match the configured API route. A
changed route requires reconciliation, preserving existing work and spending.

Provider incidents are shared across worktrees. Authentication failures remain
held until repair and a successful explicit probe. Rate limits stop new work on
that provider, permit bounded serialized recovery probes, and do not grant ticket
capacity. Independent healthy routes remain available. Summaries report provider
holds separately from ticket decisions. No spending history or ticket allowance
is reset by these changes.

Preflight distinguishes installation from execution readiness. OpenAI and
Anthropic routes use authenticated token counting; native routes additionally
exercise the installed client against a loopback provider. Other provider probe
adapters currently fail closed with an incompatible state. Token counting does
not guarantee future generation availability or model quota. No live model
request is made by these probes.

Codex uses standard-tier, ordinary metered Responses for local compaction. The
installed-client regression forces a tool call and compaction and verifies every
mock generation settles. Remote compaction endpoints remain rejected.

All new tickets require bounded admission scoping even when automatic
decomposition is disabled. Authenticated Jira descriptions supply explicit
prerequisite sections; the scoper also enumerates prerequisites. Missing links
become a dependency-reconciliation decision, which a corrected authenticated
sync can automatically return to scoping. Existing tracking parents bind their
complete authenticated child list without implementation attempts. Scope
assessments become stale when their relevant inventory changes.

## Resuming an existing installation

Run captain preflight with `--verify-runtime`. Correct provider credentials or
client compatibility before using `health-check --after-repair`; do not repeat
that flag automatically. Refresh Jira inventory and follow the controller plan,
including provider probe deadlines. Existing reservations without a frozen route
must be reconciled before native launch. Preserve budgets, Jira policy, and
paused tickets. These changes do not enable automatic decomposition or authorize
Jira relationship edits on their own.
